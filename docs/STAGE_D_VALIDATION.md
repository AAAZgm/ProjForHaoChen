# D 阶段开发与验证

日期：2026-11-05。版本：`1.1.0-beta.1`。分支：`stage-d/v1.1-development`，基于已发布的 rc.5 主分支。

状态：五项计划能力的开发、88 项自动回归、源码页面检查与最终便携包验证均已完成。2026-11-05 用户确认“没问题，功能和预期一样”，本版当前范围用户验收完成，并授权上传 GitHub。此结论依据本版反馈，不沿用 v1.0 的两台电脑反馈作为本版验收。

## 功能范围

| 计划项 | 实现 |
| --- | --- |
| 批量任务 | 多选本地视频、编辑结果加入列表、逐项导出、失败继续、取消保留成功文件、相同参数继续未完成项 |
| B 站多 P | 识别视频分 P 名称，勾选下载，按 P 顺序加入本页列表；解析与下载均在可取消子进程执行 |
| 多文件拼接 | 列表排序、不同分辨率/帧率/音轨输入统一渲染；所有来源使用同一编码方式，显卡失败整任务回退 |
| 音频导出 | M4A、MP3、WAV；逐项提取或按列表合并，保留截取、倍速、消音，无声部分补静音 |
| 方案保存/恢复 | `.qjproj` 包含原素材、剪辑设置、排列和导出选项；完整校验后恢复到独立缓存，可跨会话使用 |

入口为“3 · 批量与拼接”。原单素材流程保留；列表与剪辑工作台使用独立副本，修改后需明确更新所选列表项。方案不保存撤销历史、已导出成品、未完成任务进度或机器专属目录。

## 自动回归

`scripts/build_portable.py` 执行全部 **88 项测试，38.504 秒，通过**。其中新增 13 项 D 阶段测试，覆盖：

- 真实 FFmpeg 横屏 160×120 / 24fps / 48kHz 有声样例，与竖屏 90×160 / 15fps 无声样例合并；检查尺寸、30fps、时长、颜色顺序和补边。

## 页面与实际下载

源码启动后的两个真实 Gradio 会话通过 `scripts/check_stage_d_api.py` 检查：多文件上传、载入编辑并更新列表、混合 MP4 拼接、批量 MP3、方案跨会话恢复、取消和另一页面继续导出。浏览器实际打开新工作台，核对导入、列表、分 P、导出和方案区域的显示与控件。

真实 B 站样例 `BV1bK411W797`：识别 **23 个分 P**，仅选择 P2（`帰り道/894+羽川`）下载成功，输出 **5,138,881 字节**。此项为源码下载子进程的实网验证，不能推定所有视频、受登录限制视频或地区均可下载。首次使用视频网页提取曾返回 412，当前标准视频链接改用公开分 P 元数据接口，下载继续由 yt-dlp 执行。

本机证据：`build/stage-d-build.log`、`build/stage-d-api.log`、`build/stage-d-live/result.json`；这些生成文件不加入源码提交。

## 当前边界

- 单列表最多 100 项；方案完整原素材合计最多 20 GB。方案大小接近原素材总量，导入与恢复需要额外缓存空间。
- 本机验证环境为 Windows 11 x64；便携验证使用清理后的 PATH 和独立配置，不等于新增干净电脑验收。
- 音频导出输入仍为视频素材；没有增加独立音频文件导入或多轨时间线。
- “继续未完成任务”用于当前页面的分别导出；拼接从头执行，关闭页面后使用方案恢复编辑内容。
