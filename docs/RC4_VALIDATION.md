# rc.4 Windows 导出调度修复验证

日期：2026-10-28。此版本仍是发布候选；用户确认两台不同电脑均达到理想效果，C 阶段开发与调整后范围的用户验收已完成，公开发布另行安排。

## 改动与范围

`ffmpeg_util.run_ffmpeg()` 在新子进程进入取消监控后、读取进度前，调用 `process_performance.request_high_qos(pid)`。仅 Windows 加载系统 API；打开当前子进程的设置及有限查询权限，读取原策略后设置 `ControlMask |= EXECUTION_SPEED`、`StateMask &= ~EXECUTION_SPEED`，请求 HighQoS，最后关闭句柄。

保留计时精度等其他策略位；不修改全局电源计划、进程优先级类别、亲和性或 GPU 设置。非 Windows 跳过；API 缺失、查询/设置失败、访问被拒等只记诊断日志，继续原处理流程。导出、预览和回退重试新建的处理子进程统一走此入口。独立短编码器探测不变。

因未显式设置时由系统推断 QoS，原来查询到 0/0 不足以排除系统自动降档。依据为 [微软 SetProcessInformation 文档](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation)。因果对照及未确定的 Windows 分类触发条件见 [rc.3 诊断记录](RC3_PERFORMANCE_DIAGNOSIS.md)。

## 自动回归

构建前共 **67 项通过，0 失败、0 跳过**（18.631 秒）。新加 9 项覆盖：原策略为自动/节能/已有 HighQoS 时设置正确且保留其他位；非 Windows 跳过；API 缺失、Open/Get/Set 失败和异常时的兼容处理与句柄释放；真实 FFmpeg 在 API 不可用时仍可处理；从真实 Windows FFmpeg 子进程回读到执行速度 Control=1、State=0。

既有回归继续覆盖真实 FFmpeg 取消、半成品清理、取消后重试、显卡失败回退 CPU、AV1 解码回退、媒体时长/画面/音轨及 UI 会话行为。构建日志：`build/rc4-build.log`。

## 便携包与原片验证

最终 ZIP 在中文和空格路径 `build/portable-中文 m0p3kz30` 解压，以系统目录限定 PATH、无外部 Python/FFmpeg 的隔离环境运行，验证通过。覆盖随包 CPU 处理、真实 AV1 NVIDIA 解码/编码、MP4/GIF/预览、取消后重试、会话隔离、同名避让、设置持久化、重复启动、端口占用回退、重启恢复及导出途中退出清理。页面和本地资源检查通过；这是本地 API/资源验证，不是新的浏览器交互验收或真实 B 站链接矩阵。
